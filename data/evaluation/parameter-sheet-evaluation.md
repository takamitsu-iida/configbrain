# パラメータシートの形式差・安全性評価

実施日: 2026-11-16

## 目的と条件

列名・配置が異なる架空CSVから、同じ設定を生成できるか確認する。
対象はCatalyst 9300 / IOS XE 26.xのVLAN、アクセスポート、SVI、
同一VRF内のDHCPリレーに限定し、使用するアドレスは文書用の例示値とした。
実機への接続、現在設定との照合、到達性の検証は実施していない。

- [行形式](parameter-sheet-rows.csv)
- [列形式](parameter-sheet-columns-default.csv)
- 両方ともVLAN 120、GigabitEthernet1/0/20、SVI 192.0.2.1/24、
  DHCPサーバー198.51.100.50、デフォルトVRFを指定
- `ip routing`と`service dhcp`は既に有効と指定
- 知識ポリシーは`disallow`、検索件数は20

各形式について、実LLM APIによるセル対応付けを1回行った。対応するセルを
期待値と照合してから`--confirm`で固定形式CSVを出力し、それぞれ検索計画・
根拠検索・設定生成を1回行った。Qdrantのローカルロックを避けるため、
設定生成は順次実行した。対応付けと生成はいずれも架空の値を使用した。

## 同一設定の評価結果

| 評価項目 | 行形式 | 列形式 |
|---|---:|---:|
| 期待するセルの対応付け | 10/10 | 10/10 |
| 未解決項目 | 0 | 0 |
| 固定形式CSVの検証 | 合格 | 合格 |
| 指定設定と生成CLIの照合 | 合格 | 合格 |
| 引用IDが検索結果に存在 | 15/15 | 7/7 |

両形式から出力された固定形式CSVはバイト単位で一致し、生成コンフィグも
完全一致した。

```text
vlan 120
interface GigabitEthernet1/0/20
 switchport mode access
 switchport access vlan 120
interface Vlan120
 ip address 192.0.2.1 255.255.255.0
 ip helper-address 198.51.100.50
 no shutdown
```

両結果とも不足値、未対応要件、根拠外推測は空だった。引用の件数と警告は
一致しなかった。DHCP relayには通常のパケット転送アドレスの手順を引用したが、
両結果ともVLAN作成にはRSPAN用の手順を引用し、SVI等にはEVPN/VXLANや別用途の
文書も引用した。行形式ではアクセスポートの説明にテンプレートの確認節も引用された。
引用IDの存在やCLI一致だけでは、引用文脈の適切さは保証できない。

これは各形式1回の結果であり、再現率や実環境での正確性を示すものではない。
生成設定はレビュー用であり、投入可能とは判断していない。

## 不足・誤対応の評価

次は実LLMの予測結果ではなく、対応案を意図的に変更したオフラインの検証である。

| ケース | 観察結果 |
|---|---|
| SVI側VRFの対応を`null`にする | 未解決として固定形式CSVへの出力を拒否 |
| 対応案の作成後に入力CSVが変わる | SHA-256不一致として拒否 |
| 対応案の値だけを元セルと違う値に変更 | 値と参照セルの不一致として拒否 |
| 正しいVLAN 120ではなく、別セルの旧VLAN 121を対応付ける | **自動拒否されず、121として出力**。正しい120のセルは未対応セルに表示 |
| 対象外のNTPサーバー項目を追加 | 未対応セルに表示されるが、確認後の出力は自動では拒否されない |

後者2件は、元CSVの意味を人がレビューしなければ見落とし得る。`--confirm`は
レビューを実施したという利用者の操作であり、内容を機械的に保証するものではない。
項目の曖昧さや対象外の設定を確認・拒否する仕組みの改善が必要である。

## 改善後の検証

- 対応済みの全項目に個別確認を要求し、元の行と先頭行のセルも表示する
- 未対応の非空セルすべてに判断を要求し、必要な項目が残っている場合は出力を拒否する
- 行・列を変更した場合は確認状態を初期化し、未対応セルも再計算する
- 生成された各CLIの説明と引用先の構文・文脈を照合し、確認できなければ設定を棄権する

架空CSVを使う実LLM API実行1回では、生成CLI 8行のうちRSPANを根拠とした
VLAN作成、EVPN/VXLANの例に基づくIPアドレス設定、別用途の文書に基づく
SVIの`no shutdown`が確認できず、設定全体を棄権した。初回はMarkdown表中で
分割された物理インターフェース構文も未確認になったため、表形式の照合を修正した。
同じLLM応答と元の索引データを外部APIを再実行せずに再照合し、物理インターフェースの
引用は確認候補となり、上記3行は未確認のままであることを確認した。

標準DHCP手順を確認候補とし、RSPANの手順を拒否することも実索引で確認した。
全217テストが成功した。人が誤った対応や未対応項目を「不要」と確認すれば、
依然として誤りは通り得る。また、引用照合は定型の文字列・文脈に基づく保守的な
検査であり、意味的な妥当性を保証しない。妥当な根拠を見逃す場合もある。

## 次に行うこと

1. 架空シートで欠落・矛盾・誤対応のケースを増やし、確認負担と再実行の揺れを計測する。
2. CLIごとの関連根拠を取得・引用できるよう検索を改善し、過剰な棄権を評価する。
3. 匿名化した実際のシートが利用できるようになったら、SEの確認時間と修正件数を
   従来作業と比較する。実シートの外部送信は、情報管理と利用者の了承を前提とする。
