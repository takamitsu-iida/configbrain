# コマンドリファレンス統合の過去記録

**履歴資料。現在の作業再開には[進捗管理](../progress.md)を使用する。**
旧`docs/command-reference-design.md`を文書整理時に移動した。
本文は段階的な追記当時の記録として保持しており、「現在」「未実装」「次回」には
その後の実装・評価で更新された内容がある。現行仕様としては扱わない。
現行設計は[基本設計](../basic-design.md)・[詳細設計](../detailed-design.md)、
手順は[実装ガイド](../implementation-guide.md)を参照する。

## 1. 目的と基本方針

Catalyst 9300 / IOS XE 26.x のコマンドリファレンスを、コンフィグガイドと同じ
カタログ・取得・変換・索引・検索CLIで扱う。生成時にインターネットへ資料を探しに行かず、
ローカルで検証した同一世代の資料から、コマンドのデフォルト、モード、制約、注意事項を取得する。
CLIの入口は共用するが、保存形式と内部処理までガイドと同じにする必要はない。
リファレンスの必須要件は、コマンド名で検索でき、そのコマンドの説明全体を取得できることである。
OKF形式、PDFの章開始ページ、PDFとのページ対応はリファレンスの利用条件にしない。
ガイド側の既存のOKF・PDF照合方式は変更しない。

文書の役割は分ける。

| 文書種別 | 主な役割 |
| --- | --- |
| コンフィグガイド | 要件に対する設定手順、順序、モード遷移、事前条件 |
| コマンドリファレンス | 構文・引数の補足、デフォルト、実行モード、適用条件、副作用、履歴 |

初期導入では、実行用CLIの根拠をガイドの手順表に限定する既存ルールを維持する。
リファレンスの例から設定コマンドを追加したり、説明の掲載順を設定順序として扱ったりしない。
根拠の取得と、デフォルト設定を省略する判断は別の機能として段階的に導入する。

## 2. 現状から分かる変更点

- カタログ探索は文書種別別オプションと複数探索元に対応済み。
- ダウンロードと変換は文書IDとURLを中心に実装されているため共用できる。
  リファレンスのコマンド切り出しには章HTMLを使用する。
- 選定はカタログの全章をLLMに渡す。検索は選定された章だけを対象にする。
- 現在の文脈展開は手順節を重視する。リファレンスの `Command Default` だけがヒットしても、
  そのコマンド全体や `Usage Guidelines` を必ず取得できるわけではない。
- 現在の変換結果はHTMLアンカーの一覧を持つが、各アンカーと本文範囲の対応は持たない。
- 索引登録は文書種別ごとの読み込みに対応済み。
  ガイドは検証済みOKF、リファレンスは保存HTMLとJSONの一致を要求し、
  Qdrantへの登録はガイドだけに限定する。
- 索引は新コレクションを検証後にエイリアスを切り替える。
  一方、原本・OKF・カタログ・索引をまとめて切り替えるトランザクションはない。

既存変換処理への適合確認では、リファレンス全17章の本文・表・コードの変換と再実行は成功した。
PDF章開始ページは全章で未特定だったが、リファレンスについては対応不要とする。
一方、`vlan` と `Syntax Description` がMarkdown上で同階層になり、既存の節取得では
デフォルト説明まで含められないことを確認した。こちらを次の実装対象とする。

## 3. カタログと探索CLI

### 登録する情報

既存の文書ID、PDF URL、HTML書籍URL、章一覧を維持し、次を追加する。

- `document_type`: `configuration_guide` / `command_reference`。
- `discovery_sources`: 文書を発見した公式掲載ページまたは書籍トップのURL。
- カタログ上位の `sources`: 探索元URL、文書種別、掲載ページ／書籍トップというページ構造。

表示用の `category` は残すが、処理分岐には使わない。
文書IDは既存と同じ正規化済みPDF URLから生成し、既存ガイドのIDを変えない。
PDF URLは公式ページ上のリンクから確定する。HTML URLの拡張子を置き換えただけで、
存在や内容を確認せず登録しない。

カタログは複数探索元を正式に表現するためバージョン2とする。
既存CLIはバージョン1も引き続き読み込む。旧データに文書種別がなければ未指定のまま扱い、
勝手にガイド扱いしない。新たな探索結果の文書種別は公式URLの既知のパスで検証する。

### 探索CLI

文書種別別オプション、複数探索元、バージョン2のカタログ生成、および既存の読み込み側の
バージョン互換対応まで実装済み。PDF取得は既存CLIを共用し、後述の文書選択に対応する。
コマンド項目の解析・索引・根拠補完は後続段階で扱う。

コンフィグガイドとコマンドリファレンスは目的が異なる文書体系であるため、
利用者向けのオプションはページの粒度ではなく文書種別で分ける。

- `--configuration-guide-url`: コンフィグガイドの探索元URL。
- `--command-reference-url`: コマンドリファレンスの探索元URL。

どちらも繰り返し指定可能にする。一覧ページから文書を探索するか、指定された文書の
目次から章を探索するかは、取得したページ構造に応じて内部で処理する。
オプションで指定された文書種別と取得した文書が一致しなければエラーにする。
既存の `--seed-url` は `--configuration-guide-url` の互換用の別名として残す。
この互換指定でも文書種別を検証し、任意の文書をガイドとして登録しない。
探索元を省略した再実行では、指定出力先の既存カタログに記録された探索元を再利用する。
探索元を明示した場合はそれを完全な探索元集合とし、除外・削除候補を表示する。

```sh
uv run python scripts/discover_manuals.py \
  --product catalyst9300 \
  --release 26.x \
  --configuration-guide-url https://www.cisco.com/c/en/us/support/switches/catalyst-9300-series-switches/products-installation-and-configuration-guides-list.html \
  --command-reference-url https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/26-x/command_reference/b_26x_9300_cr.html \
  --output data/catalog/c9300-iosxe26.candidate.json
```

すべての探索元から得た文書を正規化済みURLで重複排除してから差分を取る。
探索元の取得失敗や不正な文書種別の衝突があれば、既存カタログを更新しない。
別製品・別リリース、想定外のリダイレクトは受理しない。

## 4. 取得・変換・保存

新しいリファレンス専用ダウンローダーは作らない。既存の次のCLIを使う。

1. `download_manuals`: PDF取得、更新判定、ハッシュ保存。
2. `convert_manual`: 文書種別に応じて、ガイドのOKF変換またはリファレンスのコマンド単位抽出を行う。
3. `search_commands`: リファレンスの保存済みHTML・コマンドデータを検証し、名前・モード・親で検索する。
   リファレンスにQdrant登録は要求しない。`index_manuals`はガイド用の既存処理を維持し、
   混在カタログの検証とガイドだけの索引登録には対応済み。
   選定されたリファレンス章の文書種別分岐と、ガイド構文からの文脈補完にも対応済み。

`download_manuals`には繰り返し指定可能な`--document-id`を追加し、
候補カタログから新規リファレンスだけを取得できるようにする。省略時は従来どおり全文書を扱う。
未知のIDは通信前に拒否する。PDFと更新状態を一時保存してから置換し、
状態ファイルの置換失敗時は既存PDFを復元する。復元失敗時はバックアップの場所を明示して保持する。
文書選択とこの保存失敗時の保護は実装済み。取得済みリファレンスPDFは参考資料として残すが、
コマンド検索にPDFの解析・ページ特定を要求しない。

PDF保存先の `data/source_manuals/<document_id>/` と、ガイドのOKF保存先
`data/okf/<document_id>/` は維持する。リファレンスの保存形式は次のとおり。

```text
data/command_references/<document_id>/
  commands.json
  html/<chapter_order>.html
```

取得した章HTMLを保存し、そこから抽出したコマンドの本文・節・検索用情報を
`commands.json` に記録する。OKFや章全体のMarkdownを経由することは必須にしない。
JSONには製品・リリース、元URL、HTMLファイルのハッシュ、抽出処理の版を含める。
既存のURL検証、一時保存、成功後の置換を再利用し、取得・抽出失敗時に旧データを失わない。

### コマンド単位の抽出と保存

各項目に以下を記録する。

- 文書内の項目ID、章、コマンド名、元URLとHTMLアンカー。
- コマンド項目全体の本文。表・リスト・コードの関係を保持する。
- 構文、引数説明、デフォルト、モード、履歴、利用上の注意、例、関連項目の本文と原文位置。
- 明示的に説明されるサブコマンドの名前と、その親項目・該当範囲。
- 項目の切り出し状態。境界不明や重複は明示し、確定した項目に混ぜない。

Markdown化する前のHTMLで、コマンド項目コンテナと目次アンカーを使って境界を決める。
見出しレベルだけには依存しない。同じレベルの `Syntax Description` などが存在するためである。
原文位置には保存済みHTMLの要素IDやDOM上の位置を使い、PDFページやOKF行を要求しない。
検索結果から元のHTML断片まで追跡できるようにし、別コマンドの説明を含めない。

デフォルト記述は `Command Default` に限定しない。
`vlan` 項目の `Usage Guidelines` 内にある
`media` → `ethernet (the default)` のような入れ子も、親子関係と周辺条件を保持する。
`vlan` 自体の `Command Default: None` と、子の `media` のデフォルトを混同しない。

初期版では、コマンド項目全体と原文位置・親子関係を取り出し、コマンド名で検索可能にする。
すべての英語説明から確定的なデフォルト値を自動抽出する汎用エンジンは作らない。
構造を認識できない記述は未解析として残し、LLMの推測でコマンド境界を埋めない。

この抽出・ローカル検索は実装済み。`convert_manual --reference-output`で保存先を指定し、
`search_commands --reference-root`で読み込む。省略時は`data/command_references/`を使う。
項目境界は章直下の`article.reference`、節はその内部のコンテナ・意味見出しで識別する。
目次不一致は警告、重複アンカーや入れ子の不明確な境界は未解析として記録する。
サブコマンドはモードを明記した導入文に続くリストだけを認識し、残りを推測しない。
検索時は全章の保存HTMLのハッシュと抽出結果を再検証してから名前索引を作る。
`unique_match`、`candidate`、`ambiguous`、`not_found`、`unparsed`を区別し、
サブコマンドはモードと親の両方が指定された場合だけ一意一致にできる。
文書全体の未解析有無も`coverage`に残す。ガイドの文脈取得への補完は実装済み。
生成用の根拠・引用・レポートへの接続はまだ行わない。

## 5. ローカル検索と文脈取得

### 全体フロー

```text
selection: ガイドとリファレンスを含む全カタログから関連章を選定
    ↓
search: 選定章内を検索
    ↓
contexts:
  ガイドの手順全体を取得
  → 手順表の構文と実行モードから関連コマンドを特定
  → ローカルのコマンド検索でリファレンスの該当項目を補完
  → 該当コマンド全体と注意事項を取得
    ↓
generation: 両資料の引用を検証し、根拠付きの設定案と補足を生成
    ↓
report: 設定手順の根拠とデフォルト・制約の根拠を分けて表示
```

外側の5段階CLIは維持し、文脈取得の内部に補完処理を組み込む。
`pipeline` 実行中にダウンロードや資料更新はしない。

### 検索方式

- リファレンスは、コマンド名と実行モード、親コマンドによる検索を基本とする。
  `commands.json` を読み込んだ名前索引で実現し、Qdrantへの登録は必須にしない。
- サブコマンド名でも親項目へ到達できるようにする。例えば `media` は
  VLAN設定モードの `vlan` 項目へ対応付け、その中の説明と共通の注意事項を取得する。
- 意味検索を追加する場合も候補発見用とし、短いCLI名やデフォルトを上位件数だけに依存させない。
- 補完対象は同一製品・リリースのローカルリファレンスに限定する。
  初回選定外の章を補完する場合も、根拠になったガイドの構文と補完理由を記録する。
  既存の「選定章内検索」は変えず、この補完を別の取得理由として区別する。
- `media` のような汎用語だけで一致させない。ガイドのVLAN設定モードと、
  リファレンスの親 `vlan` 項目内のサブコマンドという関係を確認する。
  モードや親の対応を確定できなければ候補扱いに留める。
- 一意一致、候補複数、該当なし、構造未解析を記録する。
  取得済み本文の改変やハッシュ不一致は通常の「該当なし」ではなくエラーにする。

補完には生成結果ではなく、取得済みガイドの手順表の構文を利用する。
項目内で選択され得る設定・確認コマンドを対象とし、LLM生成後に根拠を後付けしない。
既存の手順表抽出処理を共用可能な小さなヘルパーへ整理し、同じ構文解析を二重実装しない。

### 文脈と追跡

リファレンスにヒットしたら `Command Default` だけでなく親のコマンド項目全体を取得する。
他コマンドの注意事項を章全体から無差別に混ぜない。原文の黙示的な切り詰めは行わず、
入力上限を超える場合は項目単位で処理を分けるか、未処理範囲を明示する。

`contexts.json` に補完元の構文・モード、検索状態、候補項目、採用した範囲を残す。
この補完結果は元の検索JSONと検証済みコマンドデータ・保存済みHTMLから再現できるようにし、
生成前の文脈再取得・一致検証にも含める。

## 6. 生成とレポート

ガイド由来のコマンド構文IDと、リファレンス由来の説明用根拠IDを区別する。
ガイドには既存の原本PDF照合を維持する。リファレンスの説明は、保存済み公式HTMLと
そのハッシュ、コマンド項目・該当断片の対応を確認し、元URLとアンカーで引用する。
リファレンスの根拠にPDF開始ページを要求せず、HTML確認をPDF照合済みと表示しない。
引用照合は根拠の文書種別に応じて分ける。

初期実装では、ガイドだけによるCLI生成の後、説明専用の別リクエストで補足する。
説明応答は`reference_notes`だけを受け付け、CLIや設定値の変更を受け付けない。
各補足は種類・説明・適用条件・根拠IDを持ち、原文と引用位置はプログラムが付与する。
すべての補足にその項目のリファレンス根拠を必須とし、
通常の補足にも同じ項目のガイド根拠を補助引用として許可する。ガイドだけの補足は拒否する。
`default`は条件を必須とし、`conflict`はガイドとリファレンス双方の根拠を要求する。
補足の再試行は項目ごとに`--generation-rounds`を別途上限とし、
注記番号（1始まり）・違反ID・理由と前回応答を返して修正させる。
`reference_generation_requests`に項目・試行・結果・モデル・解析済み応答・エラーを保存し、
診断用の未検証応答は採用済みCLI・引用と分離する。
上限後も失敗する場合は検証済みCLIを残し、生成未完了として表示する。

レポートには次を追加する。

- コマンドのデフォルトと、その根拠・適用条件。
- 実行モード、重要な留意事項、取得できなかった情報。
- ガイドとリファレンスの記述が食い違う場合の双方の引用。
- 将来の省略判断では、省略したCLI、根拠、成立条件。

文書種別だけを理由に一方を常に優先しない。同じ製品・リリースであっても、
対象モード、VTPバージョン、VLAN範囲などの条件を確認する。
記載がないことをデフォルトの不存在やコマンド不要の根拠にしない。
構造・引用の検証と、意味・適用性に関するLLM判断は区別して表示する。

### 主張と適用条件の意味検証

補足生成と引用照合の後、説明専用の別リクエストで`assessment`、ガイドの`evidence`・`constraints`、
`reference_notes`と条件、`withheld_steps.reason`を審査する。
検証単位の全件被覆と、複合文を分解した主張の連結による原文の完全再現を検証する。
対象・操作・支持／矛盾／根拠不足と、適用可／条件付き／不明を別々に記録する。
単に引用が存在するだけでは支持とせず、主張に対応する原文の断片と判断理由を要求する。

親節の全文脈・同一項目の全対象根拠・未解決の前提を渡し、都合のよい引用だけの審査にしない。
根拠IDの項目境界と断片の完全一致を検証し、支持判定には当該説明の添付済み引用を要求する。
未引用の根拠が必要なら説明の引用修正対象とする。反証は未引用の同一項目根拠も利用する。
`confirmed`は要件に照らした適用可であり、資料の記述や生成案を実機状態の確認とは扱わない。
条件付き・不明には未解決条件を必須とする。

問題があれば、指摘された説明・条件・引用だけを修正し、引用照合と意味審査を繰り返す。
項目ごとに最大N回の審査・N−1回の修正（Nは`--generation-rounds`）とし、進展なしなら停止する。
CLI、束縛値、要件項目の状態・依存関係や手順の採否は変更できない。
不支持・検証失敗は保留表示と`partial`／`undetermined`、支持されても条件未確認なら条件付き表示と
少なくとも`incomplete`にし、いずれもパイプラインは警告付き完了とする。
旧JSONには意味検証済みという表示を追加しない。

`semantic_reviews`、`semantic_review_evidence`、`semantic_review_requests`を生成JSONのルートに保存し、
生の応答・反証と採用済み引用の再帰照合を分離する。保存済み結果の被覆・説明との一致も表示時に検証する。
意味審査はLLM判断であり、原子的分解・意味の正しさの機械的な証明やモデル独立性は主張しない。
人手ラベル正例・負例で支持／適用性を別々に評価し、全ラベル一致・不当承認ゼロを回帰ゲートとする。
モックによる制御試験と実LLMの誤承認率測定を混同しない。

### デフォルト省略の扱い

初期導入では `media ethernet` を自動削除せず、
「Ethernetはデフォルト。新規VLANなら明示設定を省略可能」という根拠付き補足を追加する。
これにより、資料追加と設定内容の変更を同時に行わず効果を評価できる。

省略機能は別段階で導入する。少なくとも次を満たす場合に限定する。

1. 対象コマンドと値に対するデフォルトの直接的な根拠がある。
2. 製品・リリース・モード・適用条件が一致する。
3. 新規オブジェクト作成、または現在値確認済みなど、省略しても目的を満たせる。
4. ユーザーが明示設定や既存値の変更を要求していない。

「作成してください」という文言だけで対象が実機に存在しないことまでは保証しない。
実機状態が不明なら省略候補を条件付きで示し、未解決の前提を残したまま完了扱いしない。
デフォルトへ戻すための `no` コマンドを自動追加することもしない。

## 7. 互換性・更新・失敗時の扱い

- カタログ読み込みは探索、取得、変換、選定、索引で同じバージョンと文書種別を解釈する。
  必要な共通検証だけを共用し、大規模なCLI再編はしない。
- ガイドの既存OKFパッケージとリファレンスのコマンドデータを別々に検証する。
  ガイドのみの旧パッケージは取り込み・単体検索で引き続き利用可能にする。
  生成パイプラインは品質のため両文書種別を必須とし、起動・再開時に事前確認する。
  欠落・改変・旧索引はLLMを呼ぶ前に診断レポートを出して停止する。
  リファレンスのコマンドデータが必要な場合、欠落を黙って無視しない。
- 索引形式と文脈・根拠処理の版を更新する。索引フィンガープリントには文書種別、
  コマンドデータと元HTMLのハッシュ、解析処理の版を含める。
- カタログ・資料・索引・根拠処理の版が変わった既存runを、新旧混在のまま再開しない。
  入力カタログ変更は現行どおり新規出力先を要求する。
  同じ入力でも文脈取得規則が変わった場合は、contexts以降を再生成する。
  過去のレポートと生成済みJSONは書き換えず、旧形式の表示は維持する。
- 初回導入は候補カタログで取得・変換・検証し、利用可能になってから稼働対象へ切り替える。
  既存文書の更新も含む場合は、原本・OKF・コマンドデータ・DBを別の候補ルートに揃え、
  変更のない資料も検証済みの同一内容を用意する。現行CLIの保存先指定を利用する。
- 索引切替だけでは資料全体の原子的な切替にならないため、初期運用では生成処理を止めた
  メンテナンス中に一式を切り替える。失敗時に戻せる旧一式を保持する。
  無停止の世代管理機構は初期スコープに含めない。
- ローカルに根拠がない場合もインターネットへ自動フォールバックしない。
  未確認を表示し、資料追加は取り込みCLIで行う。

## 9. 合格条件

2. コマンドリファレンスの新規取得・変更なし・更新・取得失敗を確認できる。
   変換や索引登録が失敗しても、旧一式を変更せず利用できる。

4. デフォルト節だけが検索ヒットしても、該当コマンドのモードと利用上の注意を取得できる。
   隣のコマンドの `Usage Guidelines` を混ぜない。
5. 短いコマンド名が意味検索の上位件数から漏れても、名前・モード一致の補完で取得できる。
   別モードの同名コマンド、曖昧一致、構造未解析は確定一致にしない。
6. 別製品・別リリースの資料を流用しない。リファレンスは元URL・アンカー・保存済みHTMLと
   ハッシュまで追跡できる。HTML改変や壊れたコマンドデータはエラーにする。

7. 初期導入後のdemo20相当の評価では、既存の設定案を保持しながら、
   `media ethernet` のデフォルト、条件付きの省略可能性、その原文位置を表示できる。
8. 後続の省略機能では、新規・現在値確認済み・既存値不明・明示変更要求・資料矛盾を区別する。
   既存値不明や矛盾を隠して、短い設定案を完成版として返さない。
9. 既存の部分出力、引用検証、依存グラフ、旧レポート表示が退行しない。
   ガイドだけのカタログは生成パイプラインの事前確認で拒否し、不足をレポートする。
   単体の取り込み・検索CLIの互換性は維持する。
   新旧資料や処理版の混在した再開は拒否または必要な段階から再生成される。
10. 同じレベルの `vlan` と `Syntax Description` があっても、`vlan` の構文・デフォルト・
    利用上の注意・例を一つのコマンド項目として取得でき、次のコマンドの説明は含めない。
